# 生物安全网页语音助手重构需求分析

## 结论

本次在新仓库重构，不在旧仓库上继续叠加功能。目标是一个供人工测试的完整网页语音助手：复用现有 LLM、ASR、TTS 和指令识别能力，保留“实验上下文能否直答”的第一轮判断，把所有知识处理和混合检索能力收敛到 RAGFlow，并提供历史、纠错和知识库管理页面。

需求里的 `FLOWRAG` 统一理解为 `RAGFlow`。

## 已确认输入

- 旧项目：`/cache/hanqingzhe/biosafe-rag`，只读参考。
- 新项目：`/cache/hanqingzhe/new_biosafe`。
- Python 环境：conda `biosafe`。
- RAGFlow：已验证 Web 首页和带鉴权的 `GET /api/v1/datasets` 可访问。
- 当前 RAGFlow 已存在一个空的 `biosafe` 数据集，`chunk_method=naive`；自动测试不修改它。
- 种子 Excel：1 个 sheet，85 行（1 行表头 + 84 行数据），字段为 `timestamp, question, answer, original_answer, references`。

## 功能范围

### 网页助手

- 参考微信小程序的信息结构，而不是直接转换小程序代码。
- 实验场景选择、文本输入、浏览器录音、流式状态、回答、引用展开、历史浏览和纠错输入。
- 清晰展示当前路径：指令、直答或 RAG；内部实现细节不作为页面说明文案堆叠。
- 引用按回答中的编号关联，允许查看文档名、片段、页码/位置、数据集、相似度和原文入口。

### 查询链路

- 第一轮 LLM 携带实验提示词统一返回 FuncCall、direct answer 或严格 RAG 标记；FuncCall 仅允许既有命令白名单和空参数。
- LLM 不能可靠回答或结构化决定无效时，使用用户原始问题进入 RAG。
- RAG 请求使用用户原始问题和配置的数据集 ID，不做本地查询改写或槽位增强。
- RAGFlow 返回片段后，由现有 LLM 生成最终答案并输出稳定引用编号。
- 检索为空、超时和合成失败要有明确失败语义，不把第一轮“不知道”文本伪装成成功直答。

### 历史与纠错

- 展示原始问题、RAGFlow 参考文献、系统回答和纠错回答。
- 成功问答异步交给独立强模型重新回答，展示任务状态、模型建议和公开来源；该建议只供审计和人工采纳。
- 人工纠错仍是显式写入，可修改且可审计；模型建议不得自动覆盖人工纠错。
- 不提供历史相似问答检索，不用纠错答案自动影响后续回答。

### 知识库管理

- 管理 RAGFlow datasets 和 documents：列表、创建模板库、上传、解析状态、失败原因、重试、删除和检索预览。
- 应用不自行解析、分块、向量化或重排。
- 根据 dataset 级 chunk method 提供法规、手册、表格、论文、通用资料模板；其他内置类型按需启用。

### 数据初始化

- Excel 仅初始化本地历史和前期测试问题。
- 映射：`original_answer` 是历史系统回答，`answer` 是纠错/评估后回答，`references` 解析为引用 JSON。
- 导入幂等且输出新增、跳过、错误统计；原文件保持本地，不提交。

## 明确删除或不重建

- 小程序运行形态和旧 `demo-fronted`。
- 历史问答向量库、相似问答短路、审核后自动发布闭环。
- CatalogManager、slot parser、角色分类、查询增强。
- 本地 Milvus、embedding、BM25、RRF、块级升格和自研文档处理流水线。
- 独立评估 SQLite 和复杂跨库逻辑关联。

## 验收标准

1. 文本问题能稳定走通 FuncCall、direct、RAG 三条路径，事件与持久化结果一致。
2. RAG 路径调用 RAGFlow 原始问题检索，回答中的引用能对应持久化的 RAGFlow chunk 快照。
3. 浏览器录音可完成 ASR -> 查询 -> TTS，并能取消、重试和处理失败。
4. 历史页面可查看四项核心信息、异步模型建议及状态并保存人工纠错，二者都不会改变后续检索。
5. 管理页面能真实操作开发前缀数据集和文档，并显示异步解析状态。
6. Excel 可重复导入且第二次不产生重复历史。
7. 没有密钥、本地数据库、运行日志或大文件进入 Git。
8. 后端测试、前端测试/构建、RAGFlow contract/live smoke 和关键 Playwright 流程有真实结果记录。

## 风险与处理

- RAGFlow 版本差异：先建立 client adapter 和 live contract probe，不让响应字段扩散到业务层。
- dataset 的 chunk method 是库级配置：采用少量模板库，文件上传时先选库，不能在单文件上假装切换解析方式。
- RAGFlow 引用字段可能因文件类型不同：保留原始 metadata 快照，同时归一化前端字段。
- 第一轮直答可能误判：使用严格结构化决定、超时和解析失败默认进入 RAG，不引入第二套分类/改写链路。
- 需求文件中密钥已经明文出现：保持本地忽略，开发完成后应轮换该 token。
