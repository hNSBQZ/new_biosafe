# Phase 6 - 前端路由与本地启动设计

## 目标

- 将人工演示工作台聚焦为“实验场景 -> 文本/语音模式 -> 对话结果”的主流程。
- 将知识库管理从系统面板拆到独立 `/knowledge` 路由，避免演示功能和管理员功能混排。
- 提供由 Python 读取 `.env` 的统一 API 启动入口，同时输出控制台日志和 Git 忽略的滚动日志文件。
- 在验收和运维文档中说明管理员账号的配置来源、启动命令、访问地址和日志位置。

## 非目标

- 不改变 FuncCall、LLM 直答、RAGFlow 检索和 LLM 合成四条在线结果路径。
- 不引入本地检索、查询改写、历史答案短路或纠错自动发布。
- 不改变现有 API、WebSocket 协议、SQLite 表结构或 RAGFlow 资源边界。
- 不在代码、页面或文档中展示真实管理员密码、token 或 API key。

## 受影响模块

- `web/src/App.tsx`：浏览器路由、场景选择、文本/语音模式切换和页面信息层级。
- `web/src/styles.css`：演示工作台、独立管理页和响应式布局。
- `web/src/App.test.tsx`：路由与模式切换回归测试。
- `biosafe/config.py`、`biosafe/logging.py`：日志文件配置和滚动文件输出。
- `scripts/run_api.py`：加载 `.env`、校验启动参数并运行 Uvicorn。
- `.env.example`、`验收文档.md`、`doc/06-operations/`：配置和运行说明。

## 路由与接口

前端采用浏览器 History API，不增加路由依赖：

| 路径 | 页面 |
| :--- | :--- |
| `/` | 助手演示，实验场景选择、文本/语音切换、消息和引用 |
| `/history` | 历史与人工纠错 |
| `/system` | 只读运行状态 |
| `/knowledge` | 管理员登录和 RAGFlow 知识库管理 |

Vite 开发服务器由 SPA fallback 处理直接访问；生产反向代理也需要把这些路径回退到 `index.html`。现有后端 API 和事件格式保持不变。

## 配置与日志

- `scripts/run_api.py` 使用 `python-dotenv` 读取仓库根目录 `.env`，已有进程环境变量优先。
- `BIOSAFE_LOG_LEVEL` 控制级别，`BIOSAFE_LOG_FILE` 控制日志文件，默认 `logs/biosafe-api.log`。
- 应用日志与 Uvicorn access/error 日志写入 stderr 和按大小轮转的文件；日志格式继续使用现有 JSON formatter 和脱敏规则。
- 管理员用户名、密码和签名密钥分别来自 `BIOSAFE_ADMIN_USERNAME`、`BIOSAFE_ADMIN_PASSWORD`、`BIOSAFE_ADMIN_TOKEN_SECRET`。

## 风险与回滚

- History API 路由需要部署层支持 SPA fallback；开发环境由 Vite 提供，运维文档明确生产要求。
- 文件日志不可写时应在启动阶段直接报错，避免看似启动成功但没有日志。
- 前端改动可回滚到原单页视图，不影响后端协议和历史数据。
- 启动脚本可回滚为直接运行 Uvicorn，但 `.env` 加载和日志行为会同时丢失。

## 验证方法

```bash
conda run -n biosafe python scripts/run_api.py --help
conda run -n biosafe python -m ruff check biosafe services scripts tests
conda run -n biosafe python -m pytest tests/unit tests/integration
npm --prefix web run lint
npm --prefix web test -- --run
npm --prefix web run build
```

启动后人工检查 `/`、`/history`、`/system`、`/knowledge`，并确认 `logs/biosafe-api.log` 包含启动和 access 日志且不包含凭据。
