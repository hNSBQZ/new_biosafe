# Phase 6 - 历史与人工纠错交互收敛设计

## 目标

- 将历史页从“左侧列表 + 右侧多卡片详情”收敛为单列条目。
- 条目默认只展示问题和日期，点开后显示查看答案、模型复核、人工标注和引用操作。
- 答案、模型复核和人工标注使用独立弹窗，避免所有信息同时铺开。
- 模型建议只能转入人工标注草稿，必须再由人工显式保存。

## 非目标

- 不改变 `chat_history` 或 `answer_correction` 数据结构。
- 不新增审核发布、知识库入库或影响在线回答的逻辑。
- 不把“未保存的人工标注草稿”视为已标注。

## 受影响模块

- `web/src/App.tsx`：条目展开状态、弹窗状态、答案/模型复核/人工标注交互。
- `web/src/styles.css`：单列条目、操作区、弹窗和移动端布局。
- `web/src/App.test.tsx`：条目展开、弹窗、自动纠错和人工保存行为。

## API 与数据

- 继续使用 `GET /api/history`、`GET /api/history/{id}`、`POST /api/history/{id}/auto-correction` 和 `PATCH /api/history/{id}/correction`。
- “已人工标注”仍以服务端 `corrected_answer` 非空为准；空草稿和弹窗选择不产生持久化状态。
- 模型复核轮询只在选中记录的任务为 `pending` / `running` 时进行。

## 风险与回滚

- 风险：弹窗切换时将模型建议误存。处理：“用于人工标注”只更新本地草稿并打开编辑弹窗，仅“保存标注”发送 PATCH。
- 风险：移动端弹窗超出视口。处理：限制高度并让内容区独立滚动，窄屏操作按钮改为单列。
- 回滚：本工作段只改前端组件与样式，可独立回退，不需要数据迁移。

## 验证

- `npm --prefix web run lint`
- `npm --prefix web run build`
- 桌面和移动端浏览器截图，检查条目展开、弹窗尺寸、长文本换行与操作按钮不重叠。
