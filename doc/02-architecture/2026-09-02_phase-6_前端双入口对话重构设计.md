# Phase 6 - 前端双入口对话重构设计

## 背景与目标

当前 `web/` 已具备文本、语音、引用、历史纠错和知识库管理能力，但所有页面共用工作台侧栏与卡片式信息架构。助手首屏同时展示实验卡片、独立提问面板、消息卡片和路径检查器，用户的一问一答被拆成多个技术面板，不符合对话产品的使用预期。

本次参考旧仓库只读目录 `demo-fronted` 的连续对话结构，以及 `demo-fronted` 与 `admin-frontend` 分离的产品边界，完成以下目标：

- `/` 只承载面向用户的生物安全实验对话，采用按时间正序排列的用户/助手气泡和固定底部输入区。
- `/admin/` 承载历史纠错、系统状态和 RAGFlow 知识库管理，使用独立管理导航和页面壳。
- 旧 `/history`、`/system`、`/knowledge` 地址重定向到对应管理路径，避免已有书签失效。
- 保留实验选择、文本/语音切换、取消、回答路径、引用详情和错误恢复，但不把内部事件流水作为助手首屏的独立栏位。

## 非目标

- 不复制旧仓库的查询、语音、会话或管理实现，只参考其信息层级和对话交互。
- 不改变 FuncCall、LLM 直答、RAGFlow 检索和 LLM 引用合成边界。
- 不改变 HTTP、SSE、WebSocket、SQLite 或 RAGFlow 接口。
- 不新增历史答案短路、查询改写、本地检索或纠错自动发布。
- 不在助手端展示管理员入口说明、账号配置或内部 prompt。

## 入口与视图归属

前端继续使用一个 Vite 工程和 lockfile，避免复制依赖，但提供相互独立的用户壳与管理壳：

| 入口 | 视图 | 主要能力 |
| :--- | :--- | :--- |
| `/` | 对话助手 | 实验选择、连续消息、文本/语音输入、取消、引用抽屉 |
| `/admin/history` | 历史与纠错 | 筛选、分页、回答和引用快照、人工纠错 |
| `/admin/system` | 系统状态 | 后端、浏览器录音和当前会话状态 |
| `/admin/knowledge`、`/admin/` | 知识库管理 | 管理员登录、dataset/document、解析和检索预览 |

助手壳不渲染管理侧栏。管理壳不渲染对话输入框、消息流或实验场景面板。两个入口共享 API 类型、引用抽屉和必要的展示组件，但视觉导航和主要任务完全分离。

## 对话交互

- 消息按提交时间从上到下排列；每次提问渲染右侧用户气泡和左侧助手气泡。
- 新会话为空时展示简短欢迎状态和可点击的示例问题，不显示功能说明卡片。
- SSE/语音处理期间，助手气泡原位展示当前阶段；成功后原位替换为答案，失败或取消也保留在本轮消息内。
- 回答来源以紧凑状态标识展示；RAG 引用紧邻助手回答，点击后打开现有引用详情抽屉。
- 实验选择放入对话顶栏；底部输入区提供文本/语音分段控件。文本输入支持 `Enter` 发送、`Shift+Enter` 换行。
- 语音录制沿用点击开始、再次点击停止提交；连接、录制、处理、播放和失败状态均在输入区内反馈。
- 新消息或状态更新后将消息容器滚动到底部，但不抢占用户正在编辑的输入焦点。

## 受影响模块

- `web/src/App.tsx`：双壳路由、连续对话结构、消息顺序、输入交互和旧地址兼容。
- `web/src/styles.css`：对话视口、消息气泡、固定输入区、管理壳和移动端布局。
- `web/src/App.test.tsx`：对话顺序、键盘发送、管理入口和旧地址跳转回归。
- `web/vite.config.ts`：开发环境管理路径的 SPA fallback 保持可用。
- `doc/03-plans/2026-08-27_implementation-plan.md`：持续记录该重构检查点。
- `doc/04-progress/`：记录真实实现、验证结果和遗留问题。

## 数据与接口兼容性

请求体、SSE envelope、WebSocket 消息、引用快照和管理接口保持不变。消息顺序只调整前端内存数组的追加方式，不修改历史记录时间和数据库排序。纠错仍只通过 `PATCH /api/history/{id}/correction` 写本地历史，管理入口不会发布到 RAGFlow。

## 风险与处理

- 全视口对话可能在移动端软键盘弹出时压缩：使用 `100dvh`、固定头部/输入区和仅消息区滚动，窄屏下约束气泡最大宽度。
- 长答案、长文件名和引用元数据可能撑开页面：文本允许断行，引用按钮使用可收缩布局，页面禁止横向溢出。
- 旧路径和新管理路径可能被 History API 混淆：集中在 `viewFromPath` 与 `navigate` 中映射，并覆盖直接访问测试。
- 对话数组改为正序可能影响既有断言：增加同轮用户问题先于助手回答的 DOM 顺序断言。

## 回滚

本次只修改 `web/` 和文档。回滚对应前端提交即可恢复原工作台，后端接口、SQLite 数据、语音服务和 RAGFlow 资源均不受影响。

## 验证方法

```bash
npm --prefix web run lint
npm --prefix web test -- --run
npm --prefix web run build
git diff --check
```

浏览器验证覆盖桌面与移动视口：助手首屏、连续两轮消息、引用抽屉、文本取消、语音状态、管理三个视图、旧地址重定向、无横向滚动和控件不重叠。
