# Phase 6 - 语音流式字幕与密集引用设计

## 目标

- 语音回答在助手消息内展示稳定尺寸的播放波形，播放期间使用动画反馈，完成或失败后保留静态状态。
- TTS 每个 `audio_stream.data` 分片携带的 `text` 按 `sequence` 归入当前语音轮次，在波形下方逐段出现；最终仍以查询服务返回的完整答案为事实文本。
- RAG 回答中的每个可核查句子就近使用 `[n]` 标注，并确保引用编号只指向本次 RAGFlow 检索得到的片段。
- 前端内联引用和来源列表都展示 RAGFlow 文档名，点击后继续使用现有引用详情抽屉。

## 非目标

- 不改变指令、实验上下文直答、RAGFlow 检索、LLM 合成四条在线结果路径。
- 不增加本地检索、查询改写、重排序、历史答案短路或纠错自动发布。
- 不实现服务端音频重放或保存音频文件；波形只反映当前浏览器流式播放状态。
- 不把直答结果伪装成带知识库引用的 RAG 回答。

## 受影响模块

- `web/src/App.tsx`：语音轮次的分片/播放状态、波形与字幕、可点击内联引用。
- `web/src/styles.css`：稳定尺寸的语音条、波形动画、字幕和内联文档名。
- `biosafe/application/query_service.py`：密集引用提示、引用完整性检测和一次受约束修复。
- `biosafe/integrations/ragflow/client.py`：兼容 RAGFlow 常见文档名和知识库 ID 字段。
- `biosafe/logging.py`：引用失败的结构化诊断字段和递归凭据脱敏。
- `tests/`、`web/src/*.test.tsx`：引用修复、字段归一化和语音分片展示回归。

## 事件与数据兼容性

后端 WebSocket 事件保持不变：`audio_stream.data` 已包含 `sequence`、`text`、PCM 数据与格式信息，`audio_stream.finished` 已包含完整答案和引用。前端仅在 `TurnRecord` 内增加瞬时字段：

```text
voiceSegments: [{ sequence, text }]
voicePlayback: none | buffering | playing | completed | failed
```

这些字段不写入 SQLite，也不改变历史 API。字幕按序去重展示；播放失败或分片缺失时显示查询服务返回的完整文字，不丢失文本答案。

RAGFlow chunk 仍归一化为现有 `RetrievedChunk`。文档名读取顺序扩展为 `document_name`、`doc_name`、`document_keyword`、`docnm_kw` 及 metadata 中同名字段，最终才回退到文档 ID。

## RAGFlow 与 LLM 协作

1. RAGFlow 只接收用户原始问题和已绑定 dataset IDs，返回排序后的 chunk、文档标识、文档名、位置和相似度。
2. QueryService 给本次 chunk 编号，把编号、文档名、页码和正文交给现有 LLM。
3. LLM 必须在每个可核查句子后立即写 `[n]`；同一来源可重复引用，多来源写连续标号。
4. 服务端把“至少一个引用”和“编号不越界”作为硬校验。标题、过渡语和资料不足说明不参与句级覆盖率；其他句子漏标时只基于同一批 chunk 修复一次，修复后仍有漏标则记录 coverage warning，但不丢弃带有效引用的回答。
5. 服务端只为实际出现的编号保存 chunk 快照；前端用 `citation_index` 映射文档名、详情和原文入口。

## 引用失败日志

引用硬校验失败或句级覆盖仍不完整时，本地滚动日志保留首轮 LLM 草稿；执行过引用修复时同时保留修复稿。诊断字段包括 `request_id`、阶段、问题、耗时、RAGFlow 检索参数、两版草稿的引用编号、越界编号、未引用片段，以及本轮 chunk 的编号、chunk/document ID 和文档名。

不记录 Authorization、API key、完整 RAGFlow `raw_metadata` 或 chunk 全文。结构化 `details` 写入前继续递归脱敏；日志文件保持 Git 忽略、10 MiB 单文件和 5 个滚动备份。该日志用于本机诊断，不进入在线回答或知识库。

## 风险与回滚

- TTS 分片文本经过语音规范化，播放期间字幕可能与完整答案中的数字读法略有差异；播放完成后切换为原始完整答案。
- 句级覆盖检查只用于修复和告警，避免标题、资料不足说明或模型格式波动导致整条有效回答失败；完全无引用和越界引用仍保持硬失败。
- RAGFlow 版本字段差异通过 adapter 兼容，原始 metadata 继续作为审计快照保留。
- LLM 草稿和用户问题可能包含业务内容，只写本地忽略日志并受滚动上限约束；生产部署应按数据治理要求进一步限制访问和保留周期。
- 前端和查询服务改动可独立回滚；SQLite、RAGFlow 资源和外部服务配置不变。

## 验证方法

```bash
conda run -n biosafe python -m pytest tests/unit/test_query_service.py tests/contract/test_ragflow_client.py tests/unit/test_audio_pipeline.py
conda run -n biosafe python -m ruff check biosafe services tests

npm --prefix web run lint
npm --prefix web run build
git diff --check
```

浏览器检查覆盖语音 chunk 到达时波形开始动画、字幕按序追加、播放完成后完整答案和引用文档名可见，以及桌面/移动布局无重叠和横向滚动。
