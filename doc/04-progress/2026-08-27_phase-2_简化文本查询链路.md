# Phase 2 - 简化文本查询链路

- 状态：DONE
- 范围：
  - 新增 `QueryService` 状态机，覆盖 instruction、direct、RAG、failed、cancelled。
  - 新增保守 FuncCall detector、实验上下文提示词加载、OpenAI 兼容 LLM adapter、`POST /api/chat` SSE 和 `GET /api/experiments`。
  - RAG 路径只把用户原始问题和显式 dataset IDs 交给 RAGFlow，不做历史匹配、名录预查、槽位补全、查询改写、本地 embedding、BM25、RRF 或重排序。
  - 统一写入 `chat_history`，保存 answer_source、系统答案、RAGFlow 请求快照、引用快照、阶段耗时和失败状态。
- 关键设计：
  - 第一轮 LLM 只能返回 `{"decision":"direct","answer":"..."}` 或 `{"decision":"need_rag"}`；解析失败或 LLM 超时默认进入 RAG。
  - RAG 合成提示词要求用 `[n]` 引用，服务端校验引用编号必须反查到本次 RAGFlow 召回 chunk；缺失或越界标记为失败。
  - SSE 事件 envelope 固定为 `event, request_id, sequence, stage, data, timestamp`，终态事件在历史落库后发送。
  - FastAPI 路由保持协议转换职责；问答编排集中在 application 层，便于 Phase 3 语音链路复用。
